# Implementation Plan: Auth Screens

**Branch**: `002-auth-screens` | **Date**: 2026-05-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-auth-screens/spec.md`

## Summary

Implement the sign-in and sign-up screens using the React 19 Server Actions pattern (`useActionState` + `useFormStatus`). Two new client-side form components (`SignInForm`, `SignUpForm`) are added under `src/components/auth/`. A shared `app/actions/auth.ts` server action file handles registration (bcrypt hash + auto-login) and login (NextAuth credentials). The existing placeholder pages for `/auth/sign-in` and `/auth/sign-up` are upgraded from shells to working screens. No new dependencies required — all packages already installed.

## Implementation Phases

### Phase A: Server Actions

Create `web/src/app/actions/auth.ts`:

**`register(prevState, formData)`**:
1. Parse `email`, `password`, `name` from formData
2. Zod validate → return `fieldErrors` on failure
3. `prisma.user.findUnique` → return duplicate email error
4. `hash(password, 12)` → `prisma.user.create`
5. `signIn('credentials', { email, password, redirect: false })`
6. Return `{ success: true }`

**`login(prevState, formData)`**:
1. Parse + Zod validate → return generic error on failure
2. `signIn('credentials', { ..., redirect: false })` in try/catch
3. `CredentialsSignin` → "E-mail ou senha incorretos."
4. Other `AuthError` → "Algo deu errado. Tente novamente."
5. Non-AuthError → re-throw
6. Return `{ success: true }`

### Phase B: Form Components (parallel)

**`SignInForm.tsx`**: `useActionState(login)`, `useFormStatus`, Eye/EyeOff toggle, `callbackUrl` sanitization via `useSearchParams`, `useEffect` redirect on success, glass layout.

**`SignUpForm.tsx`**: `useActionState(register)`, `useFormStatus`, Eye/EyeOff toggle, field-level `fieldErrors`, `useEffect` redirect to `/home` on success, glass layout.

### Phase C: Page Updates (parallel)

- `sign-in/page.tsx` → import and render `<SignInForm />`
- `sign-up/page.tsx` → import and render `<SignUpForm />`

Both pages keep their existing `auth()` + `redirect('/home')` guard.

### Phase D: Verification

`pnpm type-check` → zero errors. Manual flow: sign-up → `/home`, sign-out, sign-in → `/home`, callbackUrl redirect, invalid credentials, duplicate email, password toggle.
